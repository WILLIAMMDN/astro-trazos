# Flujo de trabajo del equipo

1. No trabajar directamente sobre `main`.
2. Crear rama: `feat/nombre-corto`, `fix/nombre-corto`, `docs/nombre-corto`.
3. Commits pequeños y descriptivos.
4. Abrir Pull Request hacia `main`.
5. Cada integrante debe conservar contribuciones visibles.
6. No añadir assets externos sin registrar autor, fuente y licencia en `THIRD_PARTY_NOTICES.md`.

## Commits sugeridos
- `feat: ...`
- `fix: ...`
- `docs: ...`
- `test: ...`
- `refactor: ...`
- `chore: ...`
